# 04. 데이터 모델 (Supabase / Postgres)

> Supabase Postgres + `pgvector` 기반. 관계형 데이터·전문 검색·임베딩 매칭을 **단일 DB로 통합**.
> 아래 SQL은 `supabase/migrations/`에 그대로 반영할 초안이다.

---

## ER 개요

```
articles ──< crossview_pairs >── articles   (광역 ↔ 기초 매칭)
articles ──< comments
issues   ──< temperature_scores
issues   ──< article_issues >── articles
podcast_episodes ── (source: articles + comments)
forum_posts ──< forum_comments
moderation_logs ── (대상: 모든 AI 생성물)
```

---

## 확장

```sql
create extension if not exists vector;      -- pgvector (임베딩 매칭)
create extension if not exists pg_trgm;     -- 텍스트 유사도 보조
```

## 기사 / 댓글

```sql
-- 매체 구분
create type media_source as enum ('mbc_cb', 'okinews');     -- 광역 / 기초
create type article_kind  as enum ('news', 'youtube', 'forum_opinion');

create table articles (
  id            uuid primary key default gen_random_uuid(),
  source        media_source not null,
  kind          article_kind not null default 'news',
  external_id   text,                       -- 원본 CMS/영상 ID
  url           text,
  title         text not null,
  body          text,
  category      text,
  keywords      text[],
  published_at  timestamptz,
  embedding     vector(1536),               -- text-embedding-3-small
  raw           jsonb,                       -- 원본 페이로드
  created_at    timestamptz default now(),
  unique (source, external_id)
);
create index on articles using hnsw (embedding vector_cosine_ops);
create index on articles (source, published_at desc);

-- 옥천군청 공고(source='oc_gov', kind='notice')는 게시판 4종을 모아 raw 에 공고 메타를 둔다
-- (회의 결정 [4]). category 가 곧 게시판 한글명이고, raw.board 가 슬러그다.
--   bbsNo=36 key=232 → category='공지사항' raw.board='notice'
--   bbsNo=40 key=236 → category='고시공고' raw.board='gosi'
--   bbsNo=41 key=237 → category='입법예고' raw.board='legis'
--   bbsNo=42 key=239 → category='채용공고' raw.board='recruit'
--   external_id 'oc-notice-<bbsNo>-<nttNo>' — 단 고시공고(40)만 기존 'oc-notice-<nttNo>' 유지
--   (2026-09 이전 적재분과 중복 행이 생기지 않게). 마이그레이션 0018 이 옛 category='공고'
--   행을 '고시공고' + raw.board='gosi' 로 일괄 이관한다.
--   raw.notno   공고번호(고시공고) 또는 게시판 일련번호 · raw.dept 담당부서
--   raw.board   'notice'|'gosi'|'legis'|'recruit' — /notices ?board= 필터가 쓰는 슬러그
--   raw.deadline "YYYY-MM-DD" | null — 스크래퍼(scripts/scrape/scrape-oc-notices.ts)가 뽑은 마감일.
--     채용공고는 목록에 '접수시작일·마감일' 칸이 따로 있어 그 값을 쓰고(구조화된 값이라 오탐 없음),
--     나머지 게시판은 상세 본문에서 기간을 파싱한다.
--   raw.period  근거 원문 구간(예: "접수기간: 2026. 8. 27.(목) ~ 9. 23.(수)") | null
--   body        본문 텍스트 앞 2,000자
--   보존 규약: 상세 fetch·본문 추출 실패 시 기존 deadline/period/body 유지, 성공 건도 파싱이 null 이면
--   기존 값 유지(--reparse 로만 덮음). 기존 raw 조회 실패 시 upsert 중단.
-- /notices 는 raw->>deadline 으로 마감 임박/진행 중/기간 없음을 나누고(마감 지난 공고는 목록에서
-- 아예 숨긴다 — 회의 결정 [5]), ?board= 로 게시판 하나만 좁혀 본다.
-- components/home/action-layer.getDeadlineItems 는 deadline_items(수기)와 이 값을 합쳐 홈 마감 띠를 켠다.
-- 두 쿼리가 부분 인덱스 articles_oc_notice_deadline_idx(0018, (raw->>'deadline')
--   where source='oc_gov' and kind='notice')를 타려면 source·kind 를 **반드시** 함께 걸어야 한다
--   (category IN (…) 만으로는 인덱스 조건을 함축하지 못한다).
--   게시판 목록은 components/home/action-layer 의 NOTICE_BOARDS / NOTICE_CATEGORIES 한 곳에만 둔다.

-- 기사 사진(raw.imageUrl) — 회의 결정 [3] "기사 이미지는 옥천신문 원본 우선, AI 생성은 보완용".
--   okinews : news sitemap 의 <image:loc> 절대 https URL (예: https://cdn.okinews.com/news/photo/…/xxx.jpg)
--             단, 구형 수집(raw.source='okinews-articleList')에는 이 키가 없다 → null
--   mbc_cb  : 기사 페이지 og:image. **루트 상대경로**(/upload/mbcnews/…) 이거나 빈 문자열("")일 수 있다
--   youtube : imageUrl 키 자체가 없고 raw.thumbnail(영상 캡처)만 있다 → 표지 사진으로 쓰지 않는다
--   공개 조회는 raw 를 통째로 싣지 않고 `image_url:raw->>imageUrl` 별칭 한 칸만 select 한다
--   (lib/matching/queries.ARTICLE_PUBLIC_COLUMNS). 정규화는 lib/matching/mappers.normalizeImageUrl —
--   kind='youtube' 제외, 빈 값 제외, mbc_cb 상대경로는 https://news.mbccb.co.kr 를 붙이고,
--   https 가 아닌 URL(혼합 콘텐츠로 브라우저가 막는다)과 유튜브 호스트는 버린다 → Article.imageUrl.
--   표지 한 장 고르기는 lib/reels/pair-image.pairImage: micro(옥천신문) → macro(MBC) →
--   crossview_pairs.card_image_url(AI 생성). 원본을 쓸 때는 캡션 자리에 13px "사진 · <매체>" 출처를 붙인다.
--   외부 원본은 <img> 로 직접 건다(next/image 미사용 → next.config.ts 의 images 설정 불필요).

create table comments (
  id            uuid primary key default gen_random_uuid(),
  source        media_source not null,
  article_id    uuid references articles(id) on delete cascade,
  external_id   text,
  body          text not null,
  author_hash   text,                       -- 비식별화
  like_count    int default 0,
  sentiment     text check (sentiment in ('pos','neg','neu')),  -- Claude 분류
  published_at  timestamptz,
  created_at    timestamptz default now(),
  unique (source, external_id)
);
create index on comments (article_id);
create index on comments (published_at desc);
```

## 기능 ① 크로스뷰 매칭

```sql
create type pair_status as enum ('candidate','approved','rejected');

create table crossview_pairs (
  id             uuid primary key default gen_random_uuid(),
  article_macro  uuid references articles(id) on delete cascade,  -- MBC충북(광역)
  article_micro  uuid references articles(id) on delete cascade,  -- 옥천신문(기초)
  similarity     real,                       -- pgvector 코사인
  match_score    real,                       -- Claude 재랭킹 점수(0~1)
  summary_macro  text,                        -- AI 광역 관점 요약
  summary_micro  text,                        -- AI 기초 관점 요약
  reading_point  text,                        -- "같은 정책, 두 개의 현실"
  card_data      jsonb,                       -- 카드뉴스 구성
  status         pair_status default 'candidate',
  confirmations  jsonb not null default '{}', -- 이중 컨펌(0017): {"okinews":{"by","at"},"mbc":{…}}
  created_at     timestamptz default now(),
  unique (article_macro, article_micro)
);

-- 매칭 정확도 검증용 정답셋 (Precision@5)
create table matching_eval (
  id             uuid primary key default gen_random_uuid(),
  article_macro  uuid references articles(id),
  article_micro  uuid references articles(id),
  is_correct     boolean not null,           -- 수동 태깅
  created_at     timestamptz default now()
);
```

## 기능 ② 공론 온도계

```sql
create table issues (
  id          uuid primary key default gen_random_uuid(),
  label       text not null,                 -- 이슈명(LLM 라벨)
  keywords    text[],
  created_at  timestamptz default now()
);

create table temperature_scores (
  id              uuid primary key default gen_random_uuid(),
  issue_id        uuid references issues(id) on delete cascade,
  temperature     real not null,             -- 0~100 스케일
  frequency       real,                       -- Freq 성분
  sentiment_var   real,                       -- SentimentVariance 성분
  topic_conc      real,                       -- TopicConcentration 성분
  rank            int,                        -- TOP5 순위
  prev_rank       int,                        -- 변동 화살표
  computed_at     timestamptz default now()
);
create index on temperature_scores (computed_at desc);

-- 15분 갱신 작동률 검증용
create table temperature_runs (
  id          uuid primary key default gen_random_uuid(),
  status      text check (status in ('ok','fail')),
  detail      text,
  ran_at      timestamptz default now()
);
```

> 온도 산출: `temperature = 100 * (0.4*Freq_norm + 0.35*SentVar_norm + 0.25*TopicConc_norm)` — 가중치 α=0.4 / β=0.35 / γ=0.25 고정.

## 기능 ③ AI 팟캐스트

```sql
create type episode_status as enum ('generating','review','approved','published','failed');

create table podcast_episodes (
  id            uuid primary key default gen_random_uuid(),
  title         text not null,               -- "오늘의 충북 N월 N일" (회차 식별)
  headline      text,                         -- 내용 요약 헤드라인(codex, 40자, 0020). null 이면 화면은 대본 휴리스틱 폴백
  script        text,                         -- Claude 생성 스크립트
  audio_url     text,                         -- Supabase Storage
  duration_sec  int,
  thumbnail_url text,
  source_refs   jsonb,                        -- 사용된 기사/댓글 id
  status        episode_status default 'generating',
  reviewed_by   uuid,                         -- 운영자
  scheduled_for date,                         -- 월/수/금
  published_at  timestamptz,
  confirmations jsonb not null default '{}',  -- 이중 컨펌(0017): {"okinews":{"by","at"},"mbc":{…}}
  created_at    timestamptz default now()
);
```

## 기능 ④ 통합 공론장

```sql
create table forum_posts (
  id           uuid primary key default gen_random_uuid(),
  article_id   uuid references articles(id) on delete set null,
  author_hash  text,
  title        text,
  body         text not null,
  like_count   int default 0,
  is_flagged   boolean default false,        -- AI 모더레이션
  flag_reason  text,                          -- bot/spam/hate
  created_at   timestamptz default now()
);
create index on forum_posts (created_at desc);

create table forum_comments (
  id           uuid primary key default gen_random_uuid(),
  post_id      uuid references forum_posts(id) on delete cascade,
  author_hash  text,
  body         text not null,
  is_flagged   boolean default false,
  created_at   timestamptz default now()
);
```

## 기능 ⑤ 관리자 / 검수

```sql
create type moderation_target as enum ('crossview','podcast','temperature','forum');
create type moderation_action as enum ('approve','reject');

create table moderation_logs (
  id          uuid primary key default gen_random_uuid(),
  target      moderation_target not null,
  target_id   uuid not null,
  action      moderation_action not null,
  reason      text,
  operator    uuid,                           -- MBC/옥천 담당자
  created_at  timestamptz default now()
);
-- 검수 승인율 = approve / (approve+reject)
```

## RLS / 권한 (요약)

| 테이블 | 공개 읽기 | 쓰기 |
|--------|-----------|------|
| articles, crossview_pairs(approved), temperature_scores, podcast_episodes(published) | ✅ anon select | service_role / cron |
| forum_posts, forum_comments | ✅ 인증 사용자 작성 | 본인 + 모더레이션 |
| moderation_logs, matching_eval, *_runs | ❌ | 운영자/서비스만 |

> AI 생성물은 `status='approved'/'published'` 만 공개. 검수 전 데이터는 관리자만 조회.
